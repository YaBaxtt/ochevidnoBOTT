# Очевидно — Telegram Mini App

Магазин шуточных карточек «Очевидно»: 30 продуктов, включая 3 набора, фонарик и 5 дорогих именных грамот. Сдержанный графитовый интерфейс, новый серебряный логотип, заметные цены, плавное появление покупок, поиск, категории, избранное и коллекция.

## Посмотреть на компьютере

```powershell
npm install
npm run demo
```

Откройте http://127.0.0.1:3000. Кнопка с шестерёнкой открывает тестовую админку. Данные демо хранятся в памяти и исчезают после перезапуска.

В демо сначала показывается отдельный тестовый счёт. Пока пользователь не нажал «Подтвердить тестовую оплату», результат закрыт. Реальных списаний нет. Демо не использует токен бота и production-базу, даже если они указаны в `.env`.

## Оплата и бонусы

- Реальные карточки оплачиваются Telegram Stars через `createInvoiceLink` / `openInvoice`.
- Сервер проверяет пользователя, валюту, сумму и payload. Результат недоступен до `successful_payment`.
- Отмена окна оплаты не выдаёт карточку. При задержке платежа можно проверить статус в коллекции, не платя заново.
- За задания выдаются **бонусы**. Они используются для полной оплаты карточки: 1 бонус соответствует 1 единице цены. Списание выполняется транзакцией, повторный запрос не списывает бонусы повторно.
- Бонусы не являются Stars, TON или деньгами и не выводятся.
- TON Connect подключает собственный кошелёк пользователя и показывает открытый баланс. Приложение не получает seed-фразу, не хранит средства и не отправляет транзакции. Цифровые товары внутри Telegram оплачиваются Stars.

## Админка

Доступ в рабочем приложении — только по `ADMIN_TELEGRAM_IDS`, полученному из подписанной Telegram-сессии. В демо тестовый профиль `900000001` имеет доступ автоматически; это правило никогда не действует при реальном запуске.

Разделы: обзор, отчёты по каждому продукту, цены и тексты, промокоды, реклама, проблемы, платежи и жалобы, задания, бот. Цены, включая цены наборов, редактируются отдельно. Новые цены не меняют сумму уже созданных счетов. Изменения записываются в аудит.

### Что нового в выпуске 02

- Грамоты: бумажный лист с рамкой, печатью, подписью, именем, датой и номером. Они явно обозначены шуточными документами, не выдаются за государственные документы и не дают реальных прав. Обычные ответы имеют отдельный компактный дизайн.
- Наборы «Офисный комплект» (35 Stars), «Не беспокоить» (40) и «Папка важных бумаг» (350): состав виден до покупки; после оплаты каждый документ открывается отдельно.
- Раздел «Для богатых»: пять добровольных покупок за 100 / 150 / 200 / 500 / 1000 Stars. Это дорогие шуточные грамоты, не казино, не обещание заработка и не финансовые привилегии.
- Промокоды: бонусы или один конкретный продукт/набор, лимит людей, срок окончания, выключение. Одна активация на человека; лимит и выдача награды защищены транзакциями PostgreSQL. Промокарточку нужно открыть в каталоге и выбрать соответствующий способ оплаты.
- Кнопка остановки продаж блокирует новые заказы и новые подтверждения счетов. Уже принятый Telegram платёж всё равно обрабатывается, а коллекция остаётся доступна.
- Отчёт по каждому продукту: просмотры-дни, созданные заказы, покупки, поступления Stars, возвраты, суммы после возвратов, оплаты бонусами и нажатия «Отправить». Реальные пересылки Telegram этой кнопкой достоверно не измеряются.
- Обзор отдельно показывает нажатия `/start`, уникальных запустивших бота, посещения сегодня/за месяц, каталог и наборы. Поступления Stars и внутренние бонусы не смешиваются. Текущий баланс бота запрашивается через [`getMyStarBalance`](https://core.telegram.org/bots/api#getmystarbalance); это не обещание немедленно доступного вывода. Ошибка API не превращается в фиктивный ноль.

Пять дополнительных удобств: бесплатный образец грамоты перед покупкой; скачивание в векторном SVG без потери чёткости; настройка уменьшения движения; личная история обращений со статусами; CSV-экспорт продуктовых отчётов с защитой от формул Excel. Поведение скачивания внутри разных Telegram WebView нужно проверить на целевых телефонах; обычный браузер использует стандартный download.

### Уведомления владельцу

Жалобы покупателей, несоответствия платежей, ошибки сервера и рассылки сохраняются в разделе «Проблемы». Для каждого ID из `ADMIN_TELEGRAM_IDS` создаётся запись в постоянной очереди уведомлений. Владелец должен сначала нажать `/start` у бота — Telegram не позволяет произвольно писать пользователям. Повторные попытки и ограничение повторяющихся ошибок предусмотрены. Ошибки можно отметить решёнными в админке. Демо никому не пишет.

Это встроенные уведомления работающего сервера, не независимый мониторинг: полностью остановленный процесс или недоступная база не могут отправить сообщение сами. Для production дополнительно настройте внешнюю проверку `/health` и оповещения Railway.

### Реклама

1. Создайте объявление: заголовок, текст, необязательная HTTPS-кнопка.
2. Выберите формат: сообщение в Telegram или закрываемое окно при входе в Mini App.
3. Для рассылки выберите интерес по приобретённым продуктам: грамоты, вычисления, «Про тебя», дорогие карточки или наборы. Затем аудиторию: все разрешившие сообщения, активные за 7 дней или заданное количество последних активных.
4. Сохраните черновик, проверьте предпросмотр и нажмите «Запустить». Итоговое окно покажет текст и число получателей.
5. Следите за доставками и ошибками в разделе «Реклама». Неотправленную часть можно остановить.

Рассылки идут через постоянную очередь PostgreSQL со скоростью ниже бесплатного ограничения Telegram. `429 retry_after` откладывает повтор, блокировка бота исключает пользователя из дальнейших сообщений. После сбоя сервера очередь возобновляется. Telegram не даёт ключа идемпотентности для `sendMessage`: при падении строго между фактической отправкой и сохранением статуса возможен повтор сообщения.

Пользователь должен хотя бы раз запустить бота через `/start` и не отключать сообщения через `/stop` или профиль. Mini App сама по себе не даёт боту право писать произвольным пользователям. Платные ускоренные рассылки не используются.

Объявление при входе показывается не чаще одного раза человеку в сутки для каждой кампании, сразу закрывается и учитывает показы/переходы. Обязательной подписки нет.

Для учёта рекламы, купленной в других каналах, создайте размещение с названием, расходом и валютой (RUB/USD/Stars). Ссылка `https://t.me/ИМЯ_БОТА?start=ad_ТОКЕН` появится после подключения бота. Бот закрепляет за человеком первое отслеживаемое размещение; Mini App также принимает подписанный Telegram `start_param=ad_ТОКЕН`. Отчёт показывает пришедших, покупателей, поступления и возвраты после перехода. Разные валюты не складываются; фиктивной прибыли и придуманного ROI нет. Переход по ссылке не доказывает причинную связь рекламы с покупкой.

### Бот

Приветствие с `{name}`, текст кнопки и описание редактируются в разделе «Бот». При запуске сервер настраивает команды, описание и кнопку Mini App. Доступны `/start`, `/menu`, `/cards`, `/collection`, `/tasks`, `/profile`, `/promo КОД`, `/bundles`, `/premium`, `/about`, `/help`, `/terms`, `/paysupport`, `/support`, `/cancel` и `/stop`. В приветствии есть кнопка ввода промокода; можно прислать код следующим сообщением. Обращение `/paysupport текст` попадает в админку и очередь уведомления владельцу. Команды с личными данными работают только в личном чате.

## Реальный запуск на Railway

1. Создайте бота в https://t.me/BotFather. Токен храните в Variables сервиса Railway, не в переписке и не в репозитории.
   Новый логотип для аватара бота: `public/assets/obvious-logo-v2.png`. Загрузите его через BotFather → Edit Botpic. Иконка в самой Mini App и TON Connect уже подключена кодом.
2. Разверните репозиторий в Node-сервисе Railway и добавьте PostgreSQL в том же проекте.
3. Укажите `NODE_ENV=production`, `BOT_TOKEN`, `DATABASE_URL`, `ADMIN_TELEGRAM_IDS` и `SUPPORT_URL` по примеру `.env.example`.
4. Сгенерируйте публичный HTTPS-домен сервиса. Запишите его без завершающего слеша в `PUBLIC_APP_URL`. `ALLOW_DEMO` должен быть `0`.
5. Выполните redeploy. Сервер настроит кнопку меню бота. Для Main Mini App можно дополнительно открыть BotFather → ваш бот → Mini App и указать тот же URL.
6. Откройте бота, нажмите «Старт», затем «Открыть Очевидно». Админка появится у владельца, чей числовой Telegram ID указан в Variables.
7. Для заданий добавьте бота администратором каждого канала, создайте задание и нажмите «Проверить и включить». Проверка использует `getChatMember` на сервере.
8. Проверьте отдельного тестового бота в [тестовой среде Telegram](https://core.telegram.org/bots/webapps#testing-mini-apps), включая реальные события Stars. Локальная тестовая кнопка не заменяет интеграционный тест Telegram.

Не включайте App Sleep у Node-сервиса с long polling: он получает платежи и отправляет очередь постоянно. Схема базы создаётся и дополняется автоматически, существующие карточки и их цены сохраняются.

Подключайте только один экземпляр polling-бота с одним токеном. Подключение PostgreSQL использует TLS-настройки из `DATABASE_URL`/pg: проверка сертификатов принудительно не отключается. Для внутренней сети Railway используйте её штатный внутренний URL; для внешнего PostgreSQL — проверяемый TLS и сертификат провайдера.

Локальное демо слушает только `127.0.0.1`, не всю сеть. Боевой запуск не допускает подмену профиля заголовком демо. Подписанные данные Telegram проверяются на сервере, в том числе свежесть и повторяющиеся поля. Сумма, результат и выдача не доверяются браузеру. API ограничивает частоту запросов, промокоды имеют отдельное ограничение попыток, секреты и подробные ошибки базы не возвращаются клиенту. Это базовая защита и тесты, а не гарантия отсутствия всех уязвимостей или независимый пентест.

### TON-кошелёк

TON Connect требует публичный HTTPS-манифест. Он создаётся сервером по `/tonconnect-manifest.json` из `PUBLIC_APP_URL`, иконка доступна по `/icon-180.png`. На локальном адресе отображается объяснение, без фиктивного подключения. После публикации пользователь подтверждает соединение в своём кошельке; профиль показывает адрес и баланс mainnet или testnet.

Баланс читает TON Center. Можно добавить `TONCENTER_API_KEY`, чтобы повысить лимиты запросов. При сбое API вместо выдуманного нулевого баланса отображается сообщение об ошибке.

### Иллюстрации · выпуск 03

Созданы 20 оригинальных изображений встроенным image_gen. Первые пять сценариев имеют собственные обложки: год рождения, 10 лет назад, юбилей, сложение и время с утра. Все оригинальные PNG и точные промпты: `public/assets/art-v3/` (`prompts-main.md`, `prompts-banners.md`, `prompts-categories.md`, `prompts-tired.md`, `prompts-premium.md`). Старый логотип и исходники сохранены. Для интерфейса подготовлены WebP 360/720 px, большой главный баннер — 1440 px. Загружаются адаптивные версии с lazy loading; текст, цены и кнопки не вшиты в изображения. Галерея всех оригиналов доступна по `/art-gallery.html`.

После добавления/замены исходников пересоберите производные изображения:

```powershell
npm run assets:build
```

Скрипт использует dev-зависимость `sharp` только для изменения размера и сжатия; оригинальные PNG не меняются. Готовые WebP уже сохранены в проекте, production-серверу не требуется sharp или повторная сборка изображений.

```powershell
npm run check
npm test
```
